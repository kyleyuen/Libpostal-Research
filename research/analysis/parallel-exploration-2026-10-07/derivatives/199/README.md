Requested v8 build TUs: `address_parser.c`, `tokens.c`, and derivative `diag.c`; define `EXP_TOKEN_SLICES` with the normal CPI185 diagnostic derivative switches. The release artifact is not changed and this worker did not build or run parser/model workloads.

Counters: eligible/unsafe addresses at the span guard; payload copy calls/bytes at `tokenized_string_add_token`; view records/bytes/NUL writes at `tokenized_string_add_token_view`. Copy bytes exclude NUL and normalized-address cloning. A copy call count is a function-call count, not a heap-allocation count. Restored 185 hooks cover address-parser allocation sites, address-parser phrase searches, feature-dictionary lookups, stage totals and response bytes. They still do not cover the `tokens.c` and `string_utils.c` internal allocator paths, so this derivative cannot by itself claim fewer allocator requests or lower peak memory. The benchmark diagnostic archive is CPI185, with all three changed TUs (`address_parser.c`, `tokens.c`, `diag.c`) replaced from this candidate derivative and the `EXP_TOKEN_SLICES` define added.
