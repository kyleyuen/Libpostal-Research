## Hypothesis and change

For retained scanner tokens, the parser can keep byte offsets, lengths and types in the already-owned normalized string rather than allocate/copy one C string per token. The candidate inserts NUL at safe delimiter gaps for C-string consumers. If retained spans touch or overlap, it falls back to the original per-token-copy implementation. The guard depends on current input spans, not corpus, country or key lists. Normalization, scanner, context fill, phrase searching, feature occurrences and scoring order remain in place.

Source and patch are `sources/` and `raw/source.patch`, based on experiment 119 snapshot, commit `181737d30977adc9d287e3f7a1cfafd7277525d4`; manifest SHA-256 `eb83c36944062bb8db12add9ded4789b12d7f2b3f993463c3654cc6822b3c0fb`, patch SHA-256 `779abc346e7483f15817941c95d9e82b0a77477782034bf61d2e27508450a0b3`. Release adds `-DEXP_TOKEN_SLICES` to the experiment 119/CPI switches; it does not include experiment 198's certifier. It is not overall zero-copy: the normalized address copy remains.

The implementation may retain the full normalized string as before; gaps therefore do not add a second address-sized copy. Overlap/touching spans use the original path.

## Correctness and interpretation

The corrected v9 diagnostics and both full13 screens matched retained original ordered outputs and observed one parsing thread. The allocator-only mimalloc v2 artifact meets the measured peak-footprint ceiling on the 13 workloads, while the v1 system-allocator artifact does not. The 200,000-input exact-output lane and 78 safe public-API rows passed, and the steady-footprint suite was lower at the recorded rounded precision. The separate ctypes API harness measured 2,530,331,120 B for 199 versus 2,301,265,960 B for O000; it linked candidate static archives as shared libraries while O000 used its preserved dylib, so these are unmatched build profiles and cannot establish a blanket memory regression or reduction. Four malformed-byte API rows were excluded. No uninstrumented speed was measured, and finite/workload evidence is not a universal output proof; do not promote on a speed claim.

## Decision

Diagnostic and 13-workload correctness passed with complete CPI aggregate instrumentation. The no-PGO/system-allocator artifact exceeded the matched O000 peak, while the same-source/archive allocator-only mimalloc v2 artifact passed the measured peak comparison by 94,273,392 B. V2 uses O0 scanner and no PGO. It passed the recorded steady-footprint suite, 200,000-input valid-UTF-8 exact-output fuzz subset, and 78 safe API cases, but the ctypes API harness has a higher candidate peak under unmatched dylib/archive profiles. No uninstrumented speed was measured; no universal equivalence or blanket memory claim is made, and the candidate remains unpromoted.
