## Hypothesis and change

Hypothesis: a certified lower precision Viterbi path can reduce decoder work while preserving the original ordered labels. The candidate uses the existing exact f64 state and state-transition scores; it does not use f32 feature-score accumulation. It computes a float path and conservative error bounds, certifies every selected backpointer and final label, and falls back to original f64 Viterbi whenever the certificate is inconclusive or an edge/API condition is unsupported.

Source basis: experiment 151's measured feasibility and experiment 152's certificate proof. Experiment 154 rejected a second stored f64 fallback table on memory grounds; this candidate must reuse the already-loaded model rows and allocate only address-bounded scratch. Corpus path separation is not treated as a universal proof.

The active implementation and source patch are v3 (`sources-v3/`, `raw/source-v3.patch`); its manifest SHA-256 is `0f3de4e94d1c367930ea83361473b199cc016d2583807c92d0ddacf91c500304`. V1 is retained at `sources/`, with manifest `raw/source-manifest.sha256`, patch `raw/source.patch`, release artifact `artifacts/release/` and handoff `raw/handoff-v1.json`. V1 was rejected during source review because its M bound omitted explicit rounding growth for intermediate magnitudes. V2 (`sources-v2/`) multiplies its bound by `1 + 4(u32+u64)` to conservatively cover intermediate magnitude rounding, but only assumed round-to-nearest with FTZ/DAZ disabled. V3 adds a fail-closed AArch64 FPCR guard requiring round-to-nearest and disabling FZ/FZ16; unsupported architectures/modes use the original exact f64 path. V3 alone is handed to the benchmark worker. Base source: `research/experiments/119-component-phrase-ids/sources`; base git commit: `181737d30977adc9d287e3f7a1cfafd7277525d4`.

## Operation diagnostics

Predicted work: a lower precision decoder pass, an O(T·L²) certificate-bound scan, and O(T·L) selected-path comparisons for eligible addresses; exact f64 fallback on every inconclusive address. At each timestep the certifier scans all L² state-transition scores to recompute `eP` and `mst`, and scans L state scores plus L previous-alpha values; it also scans L² transition weights once to obtain `trmax`. The diagnostic counter named `viterbi_cert_bound_comparisons` counts only the L alternatives in the selected predecessor column per timestep plus L final-label alternatives (T·L total), not the bound scans. It reuses the existing per-address alpha/backpointer workspaces and adds no model table or heap scratch. It requires L=20 and a nonempty sequence. Ties fail strict `gap > 2δ`. NaN, infinity, float overflow, and nonzero subnormal inputs/intermediates return false and use original f64 Viterbi. There is no fixed T limit: long inputs use the context matrices already sized by the parser. V3 checks the runtime FP mode on AArch64 and falls back unless round-to-nearest is active and FZ/FZ16 are disabled; unsupported architectures also use the exact decoder. Full finite-corpus acceptance measures eligibility only; it does not prove universal equivalence or reduced total work.

Corrected separate diagnostic derivatives measured 10,305 development and 12,860 golden-v1 accepted certificate attempts, with zero fallbacks; each screen matched retained ordered output and observed one parsing thread. Recurrence predecessor-cell counts were 20,115,200 and 25,118,400; the bound scans read the same number of transition-score cells, while selected-path certificate comparisons were 1,211,860 and 1,513,120. These diagnostics are not in the release. Their O(T·L²) bound scan adds quadratic work in label count per timestep, so acceptance counts do not imply lower total decoder work or speed. Raw supplements are in `research/analysis/parallel-exploration-2026-10-07/raw/198-{development,golden}-bound-counters-supplement1/`. V1/v2 releases and handoffs are immutable.

### Model-free helper checks

To stress runtime edge behavior without parser/model tests, `tools/model_free_helper_test.py` extracts the exact v3 original f64 decoder and certified decoder function bodies into `raw/helper-test.c`, with minimal matrix accessors and synthetic contexts. This is helper-level validation, not a parser run or a universal proof. It compares accepted label paths to the exact source reference, reruns the exact reference after candidate rejection, and checks that score input matrices are unchanged. One-item, multi-item, and 256-item clear winners certified with identical labels. A 4096-item synthetic case returned the exact fallback because the conservative bound rejected it; the source has no fixed length cutoff. Predecessor/final ties, a sub-f32 near-tie, NaN, infinity, below-float-normal and actual double-subnormal operands, float conversion/intermediate overflow, unsupported label count, empty sequence, `FE_DOWNWARD`, and FPCR FZ/FZ16 all rejected. Build and test exit codes are 0; exact command, timestamps, outputs, generated harness, and source/harness/binary hashes are in `raw/helper-test.command`, `raw/helper-build.*`, `raw/helper-test.*`, and `raw/helper-test.c`.

The recurrence carries a conservative error bound from experiment 152. Each recurrence uses three float32 additions, bounded by a `3(u32+u64)` relative-rounding allowance with a 1.001 cushion. `M` is a sum of seven nonnegative magnitudes (at most six binary64 additions); the multiplicative `1 + 4(u32+u64)` factor is exactly representable as `1 + 2^-22` in binary64 and dominates those six binary64 unit-roundoff losses by a wide margin. The same conservative factor is applied at every recurrence step; any arithmetic overflow makes the bound nonfinite and the strict gap test fails closed. This source argument plus fallback protects unsupported inputs; finite helper/corpus checks alone are not a universal certificate.

## Correctness and interpretation

Universal output equivalence is not claimed by a finite corpus. Source proof and exact fallback are required; every candidate parser comparison is against preserved experiment-000 outputs. V3's error recurrence adapts experiment 152, includes intermediate rounding growth, and fails closed on unsupported arithmetic conditions and unsupported FPCR modes. It requires RN, FZ=0, FZ16=0; ties fail strict gap checks; NaN, infinity, overflow and subnormal cases use original f64 fallback. It does not replace f32 score accumulation or rebuild the model score tables. The returned internal CRF score differs on a certified path; source review found the only caller is parser prediction, which discards it. Parsing remains synchronous and no persistent storage is added. This 119-derived candidate inherits existing print-features and lifecycle behavior; the independent benchmark should report these separately. Memory is still unmeasured.

## Decision

V1 rejected after source review; v2 superseded for its unchecked FP-mode assumption; v3 passed development/golden-v1 diagnostic output and thread screens plus model-free helper checks. Finite-input results do not prove universal output equivalence. All13 validation, release-memory gates, and uninstrumented speed remain pending; the quadratic bound scan is a material cost. No speed or memory improvement is claimed.
